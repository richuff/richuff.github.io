Uni-Cloud

uniCloud 是 DCloud 推出的 Serverless 云开发平台，基于 uni-app 一套代码多端发布的体系，让开发者无需自建服务器，即可在云端编写云函数、操作数据库，并直接在前端发起调用。

其**核心理念是「前端即后端」**：把云函数、数据库与前端调用封装在同一工程内，使前端工程师也能独立完成全栈业务，显著降低中小项目的协作与运维成本。

传统后端开发需要单独搭建服务器、设计接口、维护数据库与运维，前后端协作链路长；uniCloud 以云函数和 JQL 的形式将这些能力直接交给前端，省去服务端搭建与联调环节。

## 5. 查询数据库 ### 4.1 条件查询 
'use strict';
const db = uniCloud.database();
exports.main = async (event, context) => {
 	//doc(ID值)
 	let result = await db.collection("user").doc("667fed48213929f8662e8cec").get();
 	//限制获取的数据的数量
 	let result = await db.collection("user").limit(10).get();
 	//跳过前n条数据
 	let result = await db.collection("user").skip(5).get();
 	//asc顺序 desc倒序
 	let result = await db.collection("user").orderBy("_id","desc").get();
 	//过滤掉不需要的字段
 	let result = await db.collection("user").field("name":true).get();
 	return result;
};
**条件查询常用链式方法** 通过 `doc()`、`limit()`、`skip()`、`orderBy()`、`field()` 等链式方法，可灵活控制查询的范围、数量、排序与字段投影。
### 4.2 Where 查询

## 7. Schema ### 6.1 Schema 概述 每张表/集合，都有一个表名 `.schema.json` 的文件，用于描述表的信息、字段的信息。 
{
  "bsonType": "object", // 固定节点
  "description": "该表的描述",
  "required": [], // 必填字段列表
  "properties": { // 该表的字段清单
    "_id": { // 字段名称，每个表都会带有_id字段
      "description": "ID，系统自动生成"
      // 这里还有很多字段属性可以设置
    },
    "field2": { // 字段2，每个表都会带有_id字段
      "description": ""
      // 这里还有很多字段属性可以设置
    }
  }
}
