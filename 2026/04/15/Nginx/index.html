Nginx

Nginx 是一个高性能的 HTTP 与反向代理服务器，同时也可作为邮件代理服务器以及通用的 TCP/UDP 代理服务器，最初由 Igor Sysoev 编写。

其基于事件驱动（epoll）的异步非阻塞架构能够在极低资源消耗下支撑海量并发连接，是构建高并发 Web 服务与网关的核心组件。

传统服务器（如 Apache 的 prefork/worker）为每个连接分配独立的进程或线程，连接数受内存与上下文切换成本限制；Nginx 通过单 Master + 多 Worker 的事件驱动模型，从根本上解决了高并发场景下的性能与资源瓶颈。
Nginx 1.26.1

1. 概述

1.1 常用的功能模块

Nginx 常用于以下场景，主要能力模块包括：

  • 静态资源的部署
  • Rewrite 地址重写（基于正则表达式）
  • 反向代理
  • 负载均衡：轮询、加权轮询、ip_hash、url_hash、fair
  • Web 缓存
  • 环境部署：高可用的运行环境
  • 用户认证模块

1.2 核心组成

Nginx 运行时由以下核心部分组成：

  • nginx 二进制可执行文件
  • nginx.conf 配置文件
  • error.log 错误的日志记录
  • access.log 访问日志记录

3. 服务的启停

Nginx 服务的控制方式分为两类：

  • 信号控制：直接向 master 进程发送信号
  • 命令行控制：通过 nginx -s signal 发送指令

3.1 信号控制（多进程模型）

Nginx 默认采用多进程方式工作，可通过 ps -ef | grep nginx 查看进程：

root       31002       1  0 09:36 ?        
00:00:00 nginx: master process ./nginx

nobody     31003   31002  0 09:36 ?        
00:00:00 nginx: worker process

root       87869    2359  0 10:00 pts/0    
00:00:00 grep --color=auto nginx

通过向 master 进程发送信号，可以控制 worker 进程等。

3.2 信号说明

信号 作用
TERM/INT 立即关闭服务
QUIT 等待并关闭服务
HUP 重读配置文件并使用
USR1 重新打开日志文件，可用于日志切割
USR2 平滑升级到最新的 Nginx
WINCH 给所有 worker 进程发送 QUIT 指令

发送信号语法：kill -signal pid，例如：

kill -QUIT 13636
kill -QUIT `more ../logs/nginx.pid`

平滑升级流程：发送 USR2 信号给 master 进程，会重新开启对应的 master 与 worker 进程，系统中将出现两个 master 进程，新 master 的 PID 记录在 /usr/local/nginx/logs/nginx.pid，旧 master 的 PID 记录在 /usr/local/nginx/logs/nginx.pid.oldbin。随后再发送 QUIT 信号给旧 master 进程，待其处理完请求后再关闭：

kill -USR2 PID / kill -USR2 `cat /usr/local/nginx/logs/nginx.pid`

kill -QUIT PID / kill -QUIT `cat /usr/local/nginx/logs/nginx.pid.oldbin`

WINCH 信号：发送给 master 进程，让其控制 worker 进程不再接收新请求，处理完请求后关闭 worker 进程（master 进程不会被关闭）：

kill -WINCH PID / kill -WINCH `cat /usr/local/nginx/logs/nginx.pid`

3.3 命令行参数

参数 说明
-? , -h 显示帮助
-v 显示版本并退出
-V 显示版本与 configure 选项并退出
-t 测试配置文件并退出（检测 nginx.conf 语法）
-T 测试配置、打印测试文件并退出
-q 配置测试期间抑制非错误消息
-s signal 向 master 进程发送信号：stop、quit、reopen、reload
-p prefix 设置 prefix 路径（默认 /usr/local/nginx/）
-e filename 设置错误日志文件（默认 /usr/local/nginx/logs/error.log）
-c filename 设置配置文件（默认 /usr/local/nginx/conf/nginx.conf）
-g directives 在配置文件之外设置全局指令

其中 -s 信号的对应关系：

  • stop：快速关闭（类似 TERM/INT）
  • quit：等待关闭（类似 QUIT）
  • reopen：重新打开日志（类似 USR1）
  • reload：重载配置（类似 HUP）

-g 示例：

./nginx -g "pid logs/abc.pid;"

4. 配置目录结构

Nginx 配置整体分为：全局块、events 块、http 块。http 块中可以配置多个 server 块，每个 server 块又可配置多个 location 块。

4.1 配置文件整体结构

#user  nobody;
worker_processes  1;

events {
    worker_connections  1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile        on;
    keepalive_timeout  65;

    server {
        listen       80;
        server_name  localhost;
        location / {
            root   html;
            index  index.html index.htm;
        }
        error_page   500 502 503 504  /50x.html;
        location = /50x.html {
            root   html;
        }
    }
}

4.2 全局块指令

4.2.1 user 指令

用于配置运行 Nginx 服务器 worker 进程的用户和用户组。

语法 user user [group]
默认值 nobody
位置 全局块

该属性也可在编译时指定：./configure --user=user --group=group

使用步骤：

  1. 设置用户信息 www，在 nginx.conf 中配置，会报“没有该用户”的错误，此时需要 useradd www；
[root@localhost sbin]# ./nginx -t

failed in /usr/local/nginx/conf/nginx.conf:2

nginx: configuration file /usr/
local/nginx/conf/nginx.conf test failed
  1. 若将 html 目录改为 /root/html 会返回 403（权限不足），改为 /home/www/html 即可正常访问 index.html。

user 指令可以指定启动运行工作进程的用户和用户组，使系统的权限访问控制更加精细，也更加安全。

语法 master_process on | off
默认值 master_process on
位置 全局块

worker_processes 配置工作进程数量，建议与服务器 CPU 内核数保持一致：

语法 worker_processes num/auto
默认值 1
位置 全局块

4.2.3 其他全局指令

  • daemon：设定 Nginx 是否以守护进程方式启动。守护进程是 Linux 后台执行的服务进程，独立于控制终端，不会随终端关闭而停止。
语法 daemon on/off
默认值 daemon on
位置 全局块
  • pid：配置 Nginx 当前 master 进程号 ID 存储的文件路径。
语法 pid file
默认值 /usr/local/nginx/logs/nginx.pid
位置 全局块
  • error_log：配置错误日志存放路径。
语法 error_log file [日志级别]
默认值 /usr/local/nginx/logs/nginx.pid
位置 全局块、http、server、location

  • include：引入其他配置文件，使 Nginx 配置更加灵活。
语法 include file
默认值 无
位置 any

例如 include main.conf，可将部分配置写入 main.conf 中。

5. 静态资源部署

5.1 listen

语法 listen address[:port] [default_server]…
默认值 listen *:80 | *:8000
位置 server

default_server 为标识符号，用来设置默认主机：

server{
  listen 8080 default_server
}

5.2 server_name

用来设置虚拟主机服务名称，可用 127.0.0.1、localhost、域名。

语法 server_name name…;
默认值 server_name “”;
位置 server

匹配方式分为：精确匹配、通配符匹配、正则表达式匹配。

5.2.1 精确匹配

server{
  server_name www.nginx.org;
}

hosts 是一个没有扩展名的系统文件：Windows 位于 C:\Windows\System32\drivers\etc，CentOS 位于 /etc/hosts。

5.2.2 通配符匹配

通配符可以出现在开头或结尾，但不能用在域名的中部：

server{
  server_name *.richu.cn 
}

5.2.3 正则表达式匹配

由于 Nginx 配置中经常出现正则表达式，下面介绍常见用法：

  • 开始与结束：^ 匹配输入字符串的开始；$ 匹配输入字符串的结束。
  • 匹配次数：? 匹配 0 次或 1 次；+ 匹配 1 次或多次；* 匹配 0 次或多次；{n} 匹配 n 次；{n,} 至少匹配 n 次；{n,m} 匹配 n 至 m 次。
  • 匹配字符：
    • \ 用于转义
    • . 匹配除 \n 之外的任意字符
    • [xyz] 匹配 xyz 中任意一个字符
    • [a-z] 匹配任意小写字母；[^a-z] 取反，匹配除小写字母之外的任意字符
    • [A-Z] 匹配任意大写字母；[a-zA-Z] 匹配任意字母
    • [0-9] 匹配任意数字，等价于 \d；[^0-9] 匹配任意非数字，等价于 \D
    • \s 匹配任何空白字符；\S 匹配任何非空白字符
    • \w 匹配字母、数字、下划线（A-Z a-z 0-9 _）
    • x|y 匹配 x 或 y

在前面加上 ~ 表示为正则表达式：

server_name example.com ~^www\d+\.example\.com$
server_name ~^www\\.(\w+)\\.com
location / {
  return 200 $1 $2
}

$1 可以匹配到 (\w+) 中匹配的内容。

5.2.4 匹配执行顺序

精确匹配 → 通配符在开始 → 通配符在结尾 → 正则表达式 → 默认 default_server。

5.3 location

用来设置请求的 URL。

语法 location [ = | ~ * ^ | @] uri{…}
默认值 —-
位置 server, location
  • = 用于不包含正则表达式的 uri 前，必须与指定内容精确匹配：
location =/abc {
  
}
  • ~ 正则匹配，区分大小写；~* 正则匹配，不区分大小写。
  • ^~ 用于不包含正则表达式的 uri 前，功能与不加符号一致，唯一不同是：若模式匹配则停止搜索其他模式。

5.4 root 与 alias

root：设置请求的根目录。

语法 root path
默认值 root html
位置 http、server、location

alias：用来更改 location 的 url。

语法 alias path
默认值 —-
位置 location
  • root：root 路径 + location 后面的地址
  • alias：不会加上 location 后面的地址（alias 是目录别名的定义）

5.5 index

设置网站的默认首页。

语法 index file …
默认值 index index.html;
位置 http、server、location

后面可配置多个选项，匹配到其中一个后不再匹配后续设置。

5.6 error_page

设置网站的错误页面。

语法 error_page code … [=[response]] uri;
默认值 —-
位置 http、server、location

(1) 跳转指定页面：

error_page 404 www.richu.cn

(2) 重定向地址：

error_page 404 /50x.html

(3) 使用 location 的 @ 符号完成错误信息匹配：

server{
  error_page 404 @jump_to_error;
  location @jump_to_error {
    default_type text/plain;
    return 404 'Not Found Html'
  }
}

(4) 可选项 =[response] 将响应代码更改为另一个：

error_page 404 =200 /50x.html

flag 用来设置 rewrite 对 uri 的处理行为：

  rewrite ^/rewrite/(test)\w*$ /$1 redirect;
}
  • permanent：状态码 301，永久重定向

11. 负载均衡

将请求分配给不同的服务器。扩展方式：

  • 横向扩展：提升服务器数量
  • 纵向扩展：提升单机硬件

11.1 处理方式

用户手动选择，提供不同线路、不同服务器的链接。

11.2 四层与七层负载均衡

基于 OSI（开放式系统互联模型）：

  • 四层负载均衡：传输层，基于 IP+PORT 的负载均衡，不识别域名。
  • 七层负载均衡：应用层，基于虚拟 URL 或主机 IP 的负载均衡，识别域名。

实际使用模式常为：四层（LVS）+ 七层（Nginx）。

11.3 Nginx 七层负载均衡

11.3.1 upstream

定义一组服务器，监听不同端口的服务器。

语法 upstream name {}
默认值 ——
位置 http

11.3.2 server

指定后端服务器的名称与参数，可使用域名、IP、端口或 unix-socket。

语法 server name [parameters]
默认值 ——
位置 upstream 
upstream 服务名{
  server http://192.168.3.133:8080;
  server http://192.168.3.133:8081;
}

http://服务名   //访问

后端服务器状态：

状态 概述
down 当前 server 暂时不参与负载均衡
backup 标记为备份服务器，当主服务器不可用时用来传递请求
max_conns 设置代理服务器同时活动链接的最大数量，默认为 0
max_fails 允许请求代理服务器失败的次数，默认 1
fail_timeout max_fails 后，服务暂停的时间，默认 10s

11.3.3 down 状态

upstream 服务名{
  server http://192.168.3.133:8080 down;
  server http://192.168.3.133:8081;
}

11.4 负载均衡策略

名称 说明
轮询 默认
weight 权重，默认 1，权重越高被分配的请求越多
ip_hash 依据 ip 分配，每个访客固定访问一个后端服务
least_conn 依据最少连接方式，优先分配给连接数少的后端服务器
url_hash 依据 url 分配，相同 url 被分配到同一个后端服务
fair 依据响应时间，响应时间短的服务优先分配

11.4.1 轮询

轮询不需要做任何配置，按请求时间逐个分配到不同后端服务器。

11.4.2 加权轮询

weight=number 默认为 1，权重越大被分配请求的概率越大：

upstream webservers{
    server 192.168.100.128:8080 weight=90 ;
    server 192.168.100.129:8080 weight=10 ;
}

11.4.3 ip_hash

语法 ip_hash;
默认值 ——
位置 upstream 
upstream webservers{
  ip_hash;
    server 192.168.100.128:8080;
    server 192.168.100.129:8080;
}

11.4.4 least_conn

upstream webservers{
  least_conn;
    server 192.168.100.128:8080;
    server 192.168.100.129:8080;

11.4.5 url_hash

同一个 url 会到达同一个服务器：

upstream webservers{
  hash $request_uri
    server 192.168.100.128:8080;
    server 192.168.100.129:8080;

12. Nginx 缓存集成

12.1 proxy_cache_path

用于指定缓存文件的存放路径。

语法 proxy_cache_path path [levels=number]
keys_zone=zone_name:zone_size [inactive=time][max_size=size];
默认值 ——
位置 http
  • path：缓存路径存放地址
  • levels：指定缓存空间对应的目录，可设置 3 层，每层取 1 或 2。例如 levels=1:2 表示两层（第一次一个字母，第二次两个）；levels=1:2:2 对应 /usr/local/proxy_cache/d/20/d3。
  • keys_zone：指定名称和大小，如 keys_zone=itcast:200m
  • inactive：指定缓存数据多长时间未被访问就会删除，如 inactive=1d（1 天）
  • max_size：设置最大缓存空间，如 max_size=20g
proxy_cache_path /usr/local/proxy_cache levels=1:2 keys_zone=richu:200m inactive=1d max_size=20g;

12.2 proxy_cache

开启或关闭代理缓存。

语法 proxy_cache off | on
默认值 proxy_cache off
位置 http、server、location

12.3 proxy_cache_key

设置 web 缓存的 key 值，Nginx 会根据 key 值 MD5 哈希缓存。

语法 proxy_cache_key key
默认值 proxy_cache_key $scheme$proxy_host$request_uri
位置 http、server、location

12.4 proxy_cache_valid

对不同状态码的 URL 设置不同的缓存时间。

proxy_cache_valid 200 302 10m;
proxy_cache_valid 404 1m;
proxy_cache_valid any 1m;
# 200 302 缓存十分钟 404 缓存 1 分钟

12.5 proxy_cache_min_uses

设置资源被访问多少次之后被缓存。

语法 proxy_cache_min_uses number;
默认值 proxy_cache_min_uses 1
位置 http、server、location

12.6 proxy_cache_method

缓存哪些 HTTP 方法。

语法 proxy_cache_method GET|HEAD|POST
默认值 proxy_cache_method GET HEAD;
位置 http、server、location
