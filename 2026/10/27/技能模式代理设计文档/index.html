技能模式 AI Agent 系统设计

2026.10.27 AI
技能模式 AI Agent

技能模式（Skills Pattern）AI Agent 是一种模块化、可组合、可扩展的智能体架构。

它的核心思想只有一个：把 Agent 的能力拆成独立的"技能（Skill）"单元，每个技能封装特定领域的知识、提示词、工具和子流程，运行时再根据用户意图和上下文动态发现、加载并执行。

传统 Agent 把一切塞进一个巨型 Prompt：逻辑、工具、规则全混在一起，越堆越难维护。技能模式把它拆成”轻量内核 + 一堆自治技能”，让能力可以独立开发、独立测试、按需组合。

Draft v1.0

1. 概述

1.1 什么是技能模式 AI Agent

技能模式 AI Agent 是一种模块化、可组合、可扩展的智能体架构。它与传统 Agent 最大的区别，在于”能力”不再是写死在系统提示词里的一团逻辑，而是拆分成一个个自包含的技能单元。

1.2 设计目标

目标 描述
模块化 每个技能是自包含的独立单元，可独立开发、测试、发布
动态发现 Agent 根据上下文自动匹配和加载技能，无需硬编码
可组合 多个技能可链式调用或并行执行，形成复杂工作流
可扩展 第三方开发者可创建和分享自定义技能包
安全可控 技能在沙箱中运行，权限最小化，执行可审计
人机协作 在关键决策点引入人工审批，支持渐进式自主权

2. 核心概念

2.1 技能（Skill）

技能是 Agent 能力的原子单元，由元数据、提示词模板、工具、子技能、权限和生命周期钩子共同组成：

  • Metadata（元数据）
    • name：唯一标识符（kebab-case）
    • description：一句话描述
    • version：语义化版本
    • author：作者信息
    • triggers：触发条件列表
  • Prompt Template（提示词模板）
    • system：系统提示词
    • context：上下文注入规则
    • examples：Few-shot 示例
  • Tools（工具定义）
    • built-in：内置工具引用
    • custom：自定义工具实现
  • Sub-skills（子技能引用）
    • dependencies：依赖的其他技能
  • Permissions（权限声明）
    • capabilities：所需权限列表
  • Hooks（生命周期钩子）
    • on_load：技能加载时
    • on_execute：执行前/后
    • on_error：错误处理

技能定义示例（skill.yaml）

name: code-review
description: Review code changes for bugs, security issues, and style violations
version: 1.2.0
author: team-platypus
triggers:
  - keywords: ["review", "code review", "检查代码", "审查"]
  - patterns: ["*.diff", "*.patch", "git diff"]
  - context: ["pull_request", "code_change"]
tools:
  - built-in: [Glob, Grep, Read]
  - custom: [report_findings]
permissions:
  - read_filesystem
  - git_diff
hooks:
  on_load: load_review_checklist
  on_error: fallback_to_lint

2.2 Agent 核心（Agent Core）

Agent Core 是最小化的运行时内核，负责把”用户输入”翻译成”该调用哪个技能、怎么调”：

  • 意图路由（Intent Routing）：解析用户输入，匹配技能
  • 技能编排（Skill Orchestration）：加载、执行、卸载技能
  • 上下文管理（Context Management）：维护对话历史和技能状态
  • 工具调度（Tool Dispatch）：安全地执行工具调用
  • 记忆管理（Memory Management）：短期/长期记忆的读写

2.3 工具（Tool）

工具是技能与外部世界交互的接口，按风险分级管理：

  • ReadOnly Tools（只读安全）：file_read、search、api_get
  • SideEffect Tools（需审批）：file_write、api_post、git_commit
  • Dangerous Tools（需显式授权）：shell_exec、db_migrate、deploy

2.4 记忆（Memory）

分层记忆架构让”临时上下文”和”长期知识”各归其位：

记忆层 保留期 用途
Working Memory 单次会话 当前对话上下文
Short-term Memory 会话期间 技能状态、中间结果
Long-term Memory 持久化 用户偏好、项目知识
Episodic Memory 索引化 历史交互经验
Semantic Memory 向量化 知识库、文档

4.3 技能执行模型

# 技能执行的伪代码
async def execute_skill(
    skill: Skill,
    context: AgentContext,
    user_input: str
) -> SkillResult:
    # 1. 权限检查
    await permission_manager.check(skill.required_permissions)

    # 2. 上下文注入
    enriched_context = await context_manager.inject(
        base_context=context,
        skill_context=skill.prompt_template,
        memory=await memory_store.retrieve_relevant(user_input)
    )

    # 3. 工具绑定
    bound_tools = await tool_registry.bind(
        skill.tools,
        sandbox=skill.sandbox_config
    )

    # 4. 执行循环
    async with skill_session(skill, enriched_context) as session:
        result = await session.run(
            input=user_input,
            tools=bound_tools,
            hooks=skill.hooks,
            on_permission_required=request_user_approval
        )

    # 5. 结果持久化
    await memory_store.save(skill.name, result)

    return result

一次技能执行做了五件事

权限先于一切、上下文按需注入、工具按沙箱绑定、执行循环内可请求人工审批、结果最后落库。任何一步缺位，技能就只是”提示词”，而不是”可控的能力”。

7.3 记忆召回策略

class MemoryRetrieval:
    async def retrieve(self, query: str, layers: List[str]) -> List[Memory]:
        results = []

        if "working" in layers:
            results += self._get_working_memory()

        if "short_term" in layers:
            results += await self._redis_search(query)

        if "long_term" in layers:
            # 混合检索: 关键词 + 语义向量
            keyword_results = await self._pg_search(query)
            semantic_results = await self._vector_search(query)
            results += self._reciprocal_rank_fusion(
                keyword_results, semantic_results
            )

        if "episodic" in layers:
            results += await self._episodic_search(
                query, top_k=5, recency_weight=0.3
            )

        return self._deduplicate_and_rank(results)

Agent 框架选择

A. 技能开发快速示例

# skills/code_review/skill.py
from agent_core import Skill, tool, hook

class CodeReviewSkill(Skill):
    name = "code-review"
    description = "Review code changes for bugs and style issues"

    triggers = [
        {"keywords": ["review", "审查"]},
        {"patterns": ["*.diff", "*.patch"]}
    ]

    # 技能专属工具
    @tool
    async def report_findings(self, findings: list[dict]) -> str:
        """Report review findings in structured format"""
        return self.format_report(findings)

    # 生命周期钩子
    @hook("on_load")
    async def load_checklist(self):
        self.checklist = await self.fetch_review_checklist()

    @hook("on_execute")
    async def enrich_context(self, context):
        context["review_standards"] = self.checklist
        return context

# 注册技能
registry.register(CodeReviewSkill())

C. 关键设计决策记录（ADR）

ID 决策 理由 权衡
ADR-001 使用 YAML 定义技能 人类可读写，工具链成熟 不如 JSON Schema 严格
ADR-002 Agent 有状态 支持长对话和多步工作流 增加了状态管理复杂度
ADR-003 技能无状态 简化技能开发，易于横向扩展 状态需外部存储（记忆系统）
ADR-004 Python 为主语言 AI 生态最丰富 性能不如 Go/Rust
ADR-005 向量 + 关键词混合检索 兼顾语义理解和精确匹配 实现复杂度增加
